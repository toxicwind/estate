## Finding 1
OpenClaw, the open-source personal AI agent framework (a gateway that runs an AI agent across chat channels, voice, cron automations, and cloud workers), shipped release 2026.9.2. The release page states no publication date; the version naming and search crawl timing point to September 2026, within days of the reading day. Headline changes: support for OpenAI's gpt-6-astra (selectable via an OpenAI API-key profile or an eligible ChatGPT/Codex account, with text and image input, Responses tool calls, and reasoning controls); Swarm enabled by default, orchestrating concurrent sub-agents with structured results and live progress; faster, more responsive chat through durable history reads outside the Gateway event loop; reliable upgrades that preserve active settings, enabled skills, and default-agent ownership through automatic updates and restore Gateway restarts after Git updates; many more settings now apply without a Gateway restart; replies survive restarts (active, queued, and delegated replies recover); backups that preserve embedded NUL characters, Nix-managed config links, and reject corrupt archives; an experimental plugin UI (Settings, Labs, Custom plugin UI) letting plugins add Control UI pages and actions; experimental standalone Apple Watch Talk; Slack rich replies via Block Kit; Discord occupancy-driven meeting capture with automatic notes; and cross-agent session access now defaulting to all-session visibility. It is aimed at developers and enthusiasts who run their own always-on agent gateway.
- https://github.com/openclaw/openclaw/releases/tag/v2026.9.2 (undated)

## Finding 2
OpenAI's open-source Codex CLI (the Apache 2.0 terminal coding agent behind the Codex harness) shipped rust-v0.154.0 on September 9, 2026, five days after v0.153.4; Havoptic tracks it as the 90th Codex CLI release of 2026, shipping roughly every 1.5 days. New features: GPT-6-Astra is now available in the model picker and Amazon Bedrock catalogs; experimental worktree support creates isolated checkouts for new or forked sessions via --worktree or /worktree, with browse and resume; users can answer the agent's questions inline while Codex keeps working, using suggested choices or custom text without losing their draft; Windows sessions can now share a background Codex server, with daemon lifecycle commands and managed updates; Vim editing gains R replace mode with undo and dot-repeat plus more reliable Escape handling in legacy terminals; copying responses preserves formatting in rich-text apps. Bug fixes include coordinated MCP OAuth token refreshes that surface login challenges when refresh fails (without replaying rejected tool calls), startup no longer running workspace-controlled helpers before trust is established, and the macOS sandbox blocking terminal input injection. Chore: the deprecated codex mcp-server entry point is removed. For developers running Codex as their daily terminal coding agent, especially those on Windows or using MCP servers with OAuth.
- https://www.havoptic.com/r/openai-codex-rust-v0.154.0 (published 2026-09-09)

## Finding 3
mcp-server-servicenow, an open-source MCP server that gives AI coding agents a developer data plane into ServiceNow, shipped v0.7.0, a safety and governance release. The GitHub release page states no publication date; search metadata shows it about nine days before the reading day, so early September 2026. What it does: 19 tools over ServiceNow tables with tool annotations (readOnlyHint, destructiveHint, idempotentHint, openWorldHint) on all of them so clients like Claude Code can apply their own permission policy; a --read-only flag (or SERVICENOW_READ_ONLY) that hides the 7 write tools and, as defence in depth, refuses any non-GET request at the HTTP layer; table allow/deny lists enforced on table_name, class_name, the fixed-table tools, and the schema resource; opt-in --write-confirm that shows a record's current values and asks before update/delete via MCP elicitation; and a JSON audit log with one line per call (user, auth mode, transport, tool, table, sys_id, redacted query, outcome, duration), never logging values to stdout. Security fixes include encoded-query hardening so ../ or ?sysparm_query= inside a sys_id can no longer rewrite a request or bypass the denylist, and static MCP tokens tagged sn_auth: service-account so they are never forwarded to ServiceNow. It also adopts FastMCP 4.0 now that it is stable, so installation is simply uvx mcp-server-servicenow. For developers and platform engineers who want agents to read and update ServiceNow ITSM records without handing them the keys to the kingdom.
- https://github.com/jschuller/mcp-server-servicenow/releases/tag/v0.7.0 (undated)

## Finding 4
Mojo, Modular's Python-compatible AI-first language, is now fully open source. The timeline, per a byteiota analysis published in September 2026 (the page states no exact date): Qualcomm closed its $3.9 billion acquisition of Modular, Mojo 1.0 shipped on August 11, 2026 with its first stability guarantees, and on August 18 at ModCon 2026 in San Francisco the Mojo compiler, toolchain, and the rest of the stack went fully public under Apache 2.0 with LLVM exceptions, three years after its closed-source launch. The code lives at github.com/modular/modular. Fully open means the compiler, toolchain, and standard library are all Apache 2.0 with LLVM exceptions, so programs compiled with Mojo do not have to be open sourced. One catch: the compiler is read-only for now; external contributions are expected to open by end of 2026, while the standard library has accepted community PRs since 2024 (roughly 1,100 pull requests from 200 contributors). Version 1.0 guarantees core language syntax and semantics will not change in source-incompatible ways, standard library APIs are being tagged stable, and breaking changes ship with deprecated aliases and automated compiler fix-its. Practical facts: Mojo can import any Python library for incremental adoption; honest 2026 benchmark numbers put it at 78-119x faster than CPython on numerical computing tasks; install via uv pip install mojo with the modular.gateway.scarf.sh extra index; Linux and macOS only, Windows on the roadmap. Qualcomm's motive, per the analysis: attacking NVIDIA's CUDA moat with hardware-agnostic AI code that runs across NVIDIA, AMD, Qualcomm Snapdragon, Apple Silicon, AWS Trainium, and Google TPUs. For Python developers doing AI/ML and inference work who want to evaluate it now rather than wait for contribution access and Windows support.
- https://byteiota.com/mojo-1-open-source-python-ai-developers/ (undated)
