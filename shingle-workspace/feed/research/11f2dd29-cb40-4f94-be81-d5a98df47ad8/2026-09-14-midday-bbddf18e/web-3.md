## Finding 1
September 14 is the CISA KEV remediation deadline for GitLab CVE-2026-85706, the CVSS 10.0 unauthenticated path-traversal flaw in the repository commits API (CWE-22, missing authentication enforcement plus improper path confinement) that lets an attacker read arbitrary files — including credentials, secrets, tokens, SSH keys and database credentials — in a single HTTP request. CISA added it to the KEV catalog on September 11 with a three-day deadline under BOD 26-04, and required action includes forensic triage for potentially compromised systems. watchTowr has confirmed in-the-wild internet-wide probing beginning September 11; GitLab itself has not confirmed successful compromises, so what is confirmed today is active reconnaissance, with watchTowr warning indiscriminate exploitation is likely close behind. Fixed releases are GitLab CE/EE 19.3.2, 19.2.6 and 19.1.8, released September 10; the same cycle also patched CVE-2026-87719 (CVSS 9.9 insecure deserialization, but that one requires an authenticated Duo Chat user). Defenders should hunt logs for HTTP POST requests to /api/v4/projects/{id}/repository/commits/ URIs containing file.path parameters, and rotate credentials if compromise is suspected. No workaround equivalent to patching has been identified. (BleepingComputer story published within the last day; ThreatAft reference page updated within the last two days.)

## Finding 2
September 14 is also the CISA KEV deadline for ScreenConnect CVE-2026-84869 (CVSS 9.9, improper privilege management and missing authorization), added to the catalog September 11 with the same three-day BOD 26-04 window. The flaw is in the ScreenConnect client, not the server: in certain circumstances a file can be transferred and executed through an active remote session without authorization or host confirmation. Huntress has documented real worm-like exploitation in the wild since August 20 — modified ScreenConnect clients used to deploy four VBScript files for persistence, with attackers using social engineering to get victims to run rogue clients that then push payloads to other connected clients, producing worm-like amplification across the managed fleet. The fix is ScreenConnect 26.6.5; ConnectWise tells on-prem operators to upgrade, then reinstall host clients and update access agents. Temporary mitigation (not a substitute for patching): deselect the TransferFiles permission under Administration > Security > Roles for each role. Ransomware use is listed as unknown in the KEV entry. (SecurityWeek story from within the last day; ThreatAft reference page updated within the last day.)

## Finding 3
New reporting (published September 12) documents that the JFrog Artifactory flaws CISA added to the KEV catalog on September 11 are being chained in an active campaign that ends with a Rust-written backdoor. The chain starts with CVE-2026-42018 (CVSS 7.5): Artifactory's authentication layer incorrectly returns an internal anonymous-user token to unauthenticated callers precisely when the administrator has anonymous access disabled. That token opens limited API access, and the attackers then trigger additional high and critical-severity authentication bypass and privilege-escalation flaws to reach full administrative control, then stage and execute a Rust backdoor — Rust-compiled malware is increasingly used because compact statically linked binaries evade endpoint agents tuned for C/C++ or scripted payloads. A companion flaw in the same KEV batch is CVE-2026-42016, a token scope bypass where a token minted for applied-permissions/user against one repo path is accepted at administrative endpoints, letting attackers create admin accounts and mint full-scope tokens. CISA deadline for both is September 25. Key remediation note: this is a multi-flaw chain, so partial patching is not enough — apply ALL available security updates for the Artifactory version, not just the CVE-2026-42018 fix; if patching is delayed, restrict the web UI and API to trusted internal ranges; after patching, audit admin-account activity in Artifactory access logs back to September 1, since the campaign predates the September 11 KEV listing and its timeline is not fully scoped. With admin access the blast radius extends beyond the server: attackers can tamper with artifacts, inject trojanized packages, exfiltrate signing keys, or redirect downstream systems to attacker-controlled content.

## Finding 4
The earlier Artifactory auth-bypass flaw in this campaign's family, CVE-2026-82329 (CVSS 9.8, unauthenticated attacker can obtain administrative privileges under the default configuration), got a fresh intel update on the tracker today, September 14 — 17 days after its August 28 publication, and it is still listed as actively exploited (SSVC decision: Act; exploitability: active, automatable, total technical impact; EPSS exploit likelihood 7.7%). It was added to the KEV catalog September 2 with its own deadline already past, which reinforces the chain story: Artifactory's authentication layer is now on its second actively exploited bypass in six weeks, and self-managed instances are a persistent target class, not a one-off patch event.
