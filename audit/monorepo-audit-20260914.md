## Modularization Plan — Top 5

### 1. agent-session.ts (10,905 lines, 472 methods)
**Structure**: Single `export class AgentSession` (line 536) with ~250 `#private` methods + 222 public methods. Preceded by ~150 lines of type definitions. Already imports from `./session-advisors` (partially modularized).

**Plan** (extract in order, patch-based):
1. Extract type definitions (lines 438-535) → `agent-session-types.ts` (already exists — move types there)
2. Extract `#powerAssertion` methods → `session-power-assertion.ts`
3. Extract `#advisors` methods → `session-advisors.ts` (already exists — consolidate)
4. Extract `#irc` methods → `session-irc.ts`
5. Extract `#workPool` methods → `session-workpool.ts`
6. Extract prompt/in-flight methods → `session-prompt.ts`
7. Leave `AgentSession` as thin orchestrator (~500 lines)

**Method**: For each extraction, use `perl -i` to cut the method block and paste into new file, then add import. Never rewrite the whole file.

### 2. sed.rs (9,635 lines, 76 functions)
**Structure**: Complete sed implementation. Has `ProcessingContext`, `Command`, `Substitution`, `Transliteration` structs + compile/execute functions.

**Plan**:
1. Extract command parsing (`compile*`, `populate_*`) → `sed-compile.rs`
2. Extract execution engine → `sed-exec.rs`
3. Extract data types → `sed-types.rs`
4. Leave `sed.rs` as `mod` barrel + re-exports

**Method**: Rust `mod` declarations; move `pub` items, update `use` statements.

### 3. cursor-proto.ts (8,329 lines)
**GENERATED** — `// @generated by packages/catalog/scripts/proto-parser.ts - DO NOT EDIT`
**Plan**: DO NOT modularize. Fix the generator if output is problematic.

### 4. openai-compat.ts (7,388 lines)
**Structure**: Likely generated or catalog data. 47+ exports.
**Plan**: If generated, skip. If hand-written, split by provider (openai.ts, anthropic.ts, etc.).

### 5. auth-storage.ts (7,359 lines, 47 exports)
**Structure**: Auth storage with 47 exported functions/types.
**Plan**:
1. Group exports by concern (token storage, session, refresh, validation)
2. Extract to `auth-storage/{tokens.ts, sessions.ts, refresh.ts, validation.ts}`
3. Leave `auth-storage.ts` as barrel re-exporting all

**Method**: Move export blocks via perl, replace with `export * from`.

## Existing Modularization Conventions

- **TypeScript**: `index.ts` barrel files (e.g., `src/activity/index.ts`, `src/advisor/index.ts`)
- **Rust**: `mod.rs` files (e.g., `crates/pi-ast/src/language/mod.rs`)
- **Python**: `__init__.py` (rare in tau/engine — mostly TS/Rust)
- **Pattern**: The `session/` directory shows the convention — split by concern, barrel via `index.ts`

## Recommendations

1. **Deduplicate first**: The `tau/` ↔ `projects/tau/` duplication is the biggest waste. Determine canonical, delete or symlink the other.
2. **Don't touch generated**: `cursor-proto.ts`, `*_pb.ts` are generated — modularize the generator, not the output.

4. **Use perl patching**: For each extraction, `perl -0777 -i -pe` to move blocks. Never rewrite.
