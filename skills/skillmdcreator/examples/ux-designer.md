# Priya Sharma — Senior UX Designer

9 years designing digital products, currently at a consumer fintech (8M users). Solo designer embedded with the core banking team.

## Expertise areas

- **Interaction design** — flows, states, error handling, progressive disclosure
- **User research** — user interviews, usability testing, diary studies, synthesis
- **Design systems** — built two from scratch, including tokens, Figma libraries, documentation
- **Figma** — variables, auto-layout, component variants, branching workflows, prototyping
- **Accessibility** — WCAG 2.2 AA as baseline, screen reader testing, keyboard navigation
- **Prototyping** — ProtoPie for complex interactions, Figma for basic flows
- **Writing** — I write the UX copy myself; I don't trust it to engineering or PM
- **Data literacy** — I read Mixpanel and Amplitude, can write basic SQL

## How I work

- **Research before pixels** — I won't start high-fidelity work without user input
- **Flows before screens** — the happy path is never the whole story; I map errors, empty states, edge cases upfront
- **Low-fi → high-fi** — I iterate in sketches or greybox before touching visual design
- **Components over one-offs** — if I'm designing the same thing twice, it belongs in the system
- I prefer **written rationale** in my Figma files — future-me and handover thank me

## Design principles I follow

- **Clarity over cleverness** — if it needs a tooltip to explain, it's broken
- **Consistency over novelty** — users shouldn't have to relearn patterns within a product
- **Respect the user's attention** — every animation, modal, or notification is a tax
- **Default to accessible** — contrast, focus states, keyboard first, not retrofitted

## What I avoid

- "Make it pop" as direction — I push back for specifics
- Designing from reference screenshots without understanding context
- Copy written by engineering — I rewrite it all
- Research that confirms what you already think — I design studies to disprove hypotheses

## Current focus

Leading the redesign of the onboarding flow — current drop-off is 34% at the KYC step, target is <20%. Running usability tests weekly.

## When helping me

- Assume I know design fundamentals — skip the basics
- For UX copy, give me 3 options and explain the trade-offs
- Challenge me when a pattern I'm proposing has known accessibility issues
- For Figma questions, assume I'm using the latest version with variables
- If I ask for a flow, draw it out in text; don't just describe it prose-style
