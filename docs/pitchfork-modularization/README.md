# Pitchfork modularization (D2)

Each project owns its daemons. The supervisor config is composed, not
hand-edited.

## Layout

```
/home/toxic/sovereign/
├── parent.toml            # preamble: groups, env_file, global settings
├── projects.toml          # registry: project key -> pitchfork.d/ directory
├── attribution.json       # machine-readable daemon -> project map
├── pitchfork.toml         # GENERATED by bin/pitchfork-compose — do not edit
├── bin/
│   ├── pitchfork-compose      # the composer (Bun)
│   ├── pitchfork-split        # one-time monolith -> per-daemon splitter
│   └── pitchfork-orphan-watch # running-vs-declared drift detector
├── pitchfork.d/           # daemons owned by the parent project itself
│   └── <daemon>.toml      # one daemon per file, original text preserved
└── projects/range/ranch/flicker/
    └── pitchfork.d/
        └── flicker.toml   # owned by the flicker project, not the parent
```

Ranch projects live in the ranch repo (nested checkout): their
`pitchfork.d/` directories are committed to ranch main, e.g.
`projects/range/ranch/squawk/pitchfork.d/`.

## Design lineage: systemd drop-ins

This is the systemd drop-in pattern applied to the process supervisor.
systemd never asks you to edit the vendor unit file: packages ship fragments
in `/etc/systemd/system/foo.service.d/*.conf`, and the init system composes
them. The monolith stays untouched; each owner edits only their fragment;
conflicts surface at composition time, not in a merge conflict three weeks
later.

Same contract here:

- **One daemon per file.** `<project>/pitchfork.d/<daemon>.toml` is the
  source of truth for that daemon. Comments survive composition (the composer
  concatenates original block text, never re-serializes).
- **The parent owns the preamble.** `parent.toml` (groups, env_file, global
  settings) + `projects.toml` (the registry) live at the repo root.
- **Composition is fail-closed.** Two projects claiming the same daemon name
  is an `OWNERSHIP CONFLICT` — the composer exits 3 and writes nothing.
  There is no "last writer wins".
- **The composed file is a build artifact.** `pitchfork.toml` carries a
  `GENERATED — do not edit` header. Edit a fragment, recompose, done.

## Runbook

```bash
# add or change a daemon: edit the project's fragment
$EDITOR projects/range/ranch/squawk/pitchfork.d/squawk.toml

# validate without writing
bin/pitchfork-compose --check

# preview what would change vs the live file
bin/pitchfork-compose --diff pitchfork.toml

# cut over — pitchfork hot-reloads the toml (~2s, no supervisor restart)
bin/pitchfork-compose --out pitchfork.toml

# confirm nothing is running without an owner
bin/pitchfork-orphan-watch
```

Retiring a daemon: delete its fragment, recompose, then
`pitchfork clean --daemon <namespace>/<name>` to drop the stopped entry.

## Orphan detection

`bin/pitchfork-orphan-watch` compares what pitchfork reports as `running`
against `attribution.json`. Anything running with no declared owner is an
orphan — a daemon that would survive a recompose invisibly and a deletion
risk. Exit 0 = clean, exit 1 = orphans (JSON to stdout).
