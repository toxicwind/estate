## Finding 1
Ollama v0.34.0 shipped September 10, 2026. The headline feature is ChatGPT Desktop support: Ollama models can now be used directly inside ChatGPT Desktop, with setup available from the Ollama app on macOS. The release also improves structured output performance on Apple Silicon and adds OpenAI-compatible client tool search and response compaction. The release candidate trail (rc0 through rc5, September 4-9) shows the OpenAI-compat work in detail: rc2 finalizes OpenAI responses at the web search limit, rc3 accepts plaintext-labeled Codex agent messages, rc4 normalizes namespaced commands in Full Access, and rc5 adds support for standalone named function outputs. The previous release, v0.33.3 (September 3), added image and audio support for Gemma 4 safetensors on the MLX engine (audio clips longer than 30 seconds are chunked automatically), cached prompt token reporting, honoring GGUF-defined default parameters, and engine updates to MLX, MLX-C, and llama.cpp (bumped to b10760). TechSpot's Ollama listing, also updated September 10, 2026, additionally notes an OpenClaw channel setup (connect WhatsApp, Telegram, Discord and other messaging channels through `ollama launch openclaw`), flash attention for Gemma 4 on compatible GPUs, detection of curl-based OpenCode installs at ~/.opencode/bin by `ollama launch openclaw`, and a /save fix for safetensors-based architectures.
- https://releasebot.io/updates/ollama (published 2026-09-10)
- https://www.techspot.com/downloads/7772-ollama.html (published 2026-09-10)

## Finding 2
vLLM v0.29.0 was released September 9, 2026 (594 commits, 277 contributors, 91 new). The headline change: Model Runner V2 is now the default for all models, completing the rollout that began with pooling models; MRV1 is now considered deprecated with removal targeted at v0.32, though it still falls back for unsupported features like sequence parallelism and elastic expert parallelism. New model support includes Hy4-preview, Tencent's 770B/49B-active MoE with Gated DeepSeek Sparse Attention and native MTP; Qwen3.8-Flash-Next with BF16/FP8/NVFP4 and MTP; GraniteSWA and GraniteMoeSWA; NemotronH_Omni_Reasoning_V3 with MTP; and Kimi K3 NVFP4 checkpoints. Performance work targets Kimi-K3 (fused MXFP4 top-k finalization, DCP with DSpark) and DeepSeek V4 (shared experts fused into MegaMoE, adaptive top-k width, native SwiGLU clamp kernel). New defaults: FlashInfer all-reduce enabled by default for TP CUDA groups (opt out with VLLM_ALLREDUCE_USE_FLASHINFER=0), deterministic prefix-cache NONE_HASH, and new --max-num-queued-reqs / --max-num-queued-tokens admission-control flags. Breaking changes: ten deprecated model architectures removed, `python -m vllm.entrypoints.openai.api_server` deprecated in favor of `vllm serve`, PyAV video decoder backend removed, and VLLM_TEST_FORCE_FP8_MARLIN and VLLM_ROCM_USE_AITER_FP4_ASM_GEMM removed. Install: `pip install vllm` (PyPI, CUDA 13.0) or `docker pull vllm/vllm-openai:v0.29.0`.
- https://github.com/vllm-project/vllm/releases/ (published 2026-09-09)
- https://github.com/vllm-project/vllm/releases/tag/v0.29.0 (published 2026-09-09)

## Finding 3
llama.cpp v0.4.0 landed in early September 2026 (covered by AI Understanding on September 4; the GitHub release notes page itself states no date). New model support: initial Qwen3.8-Flash-Next (qwen4exp) architecture support with optimization improvements still pending, NVIDIA Nemotron-3-Puzzle-75B-A9B, DSpark support for Nemotron 3.5, and nanbeige4.2-3B. Memory and loading got real attention: lazy tensor reading via a new --lazy-mode flag (shorthand -lzm) loads tensors on demand instead of up front, plus a quantizer RAM cap and row-slab streaming to prevent RAM peaking at model load. Server changes: per-slot context limits, accepting data: URLs for media input, preserve_reasoning enabled by default, and rejecting prefilled assistant tool calls. Multimodal: new --video-* parameters, DeepSeek-V4-Flash-Vision-Exp support, DeepSeek-V4 input vision fixes, Gemma-4 vision fixes, and a Qwen3-TTS fix. Backend: ggml bumped to 0.23.0, adding sparse flash attention (including for DeepSeek-V4/GLM and Qwen4exp), RPC event/async APIs, and Apple RDMA transport; CUDA work includes MoE fusion extensions and concurrent streams per split for multi-GPU. The release's nightly build is b10809. Separately, since August 21, 2026 llama.cpp tags semantic-versioned vX.Y.Z stable releases (e.g. v0.2.0) that carry only a nightly-tag.txt pointer asset rather than platform binaries; the bNNNNN tag named inside has the actual binary zips.

## Finding 4
NVIDIA announced IFA 2026 optimizations (reported September 3-4, 2026) claiming up to 1.9x faster local agents through continued work with the open-source llama.cpp and vLLM communities, measured on SpeedBench-Coding 8K Throughput with AIPerf. llama.cpp on GeForce RTX 5090 shows up to a 50% token-throughput (tok/s) boost on Qwen3.6-27B and 90% on Qwen3.6-35B; RTX PRO 6000 Blackwell sees up to 20% speedup in vLLM; DGX Spark sees 1.4x on Qwen3.6-27B in vLLM and 20% on DeepSeek V4 Flash. The mechanisms are optimized kernels, improved speculative decoding (smaller draft component proposes tokens the main model verifies in batches), and faster prompt prefill; vLLM specifically gains new XQA attention kernels in FlashInfer plus backend changes. NVIDIA says the updates ship through the llama.cpp and vLLM backends and are distributed through LM Studio and Ollama. Alongside, NVIDIA announced one-click local AI setup for 24GB+ NVIDIA GPUs across Hermes Agent (Nous Research), OpenClaw, and Perplexity Portable Computer: Hermes will auto-detect the NVIDIA GPU, pick an appropriate model and configuration, and run it through integrated llama.cpp with NVIDIA's inference optimizations, removing manual model downloads and tuning; Perplexity Portable Computer is coming in September to RTX GPUs with at least 24GB VRAM on Linux and Windows, letting users run complete workflows locally without consuming credits and escalating selectively to 15+ frontier cloud models with permission.
