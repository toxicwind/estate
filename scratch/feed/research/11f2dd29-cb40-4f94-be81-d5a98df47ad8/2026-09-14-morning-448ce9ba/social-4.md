## Finding 1
In late August 2026 Tailscale released Tailcat, an open-source Go tool billed by its own GitHub repo (github.com/tailscale/tailcat) as "like netcat, but over Tailscale's data plane, without Tailscale's control plane." One side runs a listener that returns a short connection token (example shown: k9q2-7f3m-xv48); the other pastes it and an end-to-end WireGuard tunnel opens, bootstrapping through a DERP relay and then upgrading to direct peer-to-peer via NAT hole-punching. It needs no Tailscale account, no root, and touches no routes or DNS. Features covered across the posts: piping stdin/stdout, exposing local ports, SOCKS5 proxying, an exit-node mode, ephemeral or saved keys, a browser WebAssembly demo, and even an auth-free SSH server. Install is one line: `go install github.com/tailscale/tailcat/cmd/tailcat`. License is BSD-3. Posts tracked its growth from about 950 stars in its first 24 hours to roughly 2,800-3,900 stars within days. Technical posts flag the caveats: the API and CLI carry no stability promise, public DERP relays have no uptime guarantee, and it is meant for temporary tunnels, not production services; commenters note you can run your own DERP relay to cut the Tailscale dependency entirely. The Sept 1 Threads post from @jadu101x (190 followers, 15 likes) frames it as a tool for the AI-agent era: agents now spin up VMs and need safe handoff, and temporary peer connections like Tailcat make cloud coding agents easier to inspect locally. Contributors to that thread call it a case study in development tools designed for agents rather than humans.

## Finding 2
A hardening consensus surfaced this week among homelab and security creators, converging on the same checklist. On Sept 12, Victor (@iamjustvick, 25K followers) walked through securing a Proxmox and Jellyfin server for remote management: create a VM, install Tailscale, enable IP forwarding, advertise the home network as a subnet router, approve it in the Tailscale admin console, test remote access with phone Wi-Fi off to prove it works externally, audit exposed ports, and harden SSH. The same day, cybersecurity creator Day Johnson (@daycyberwox, 3.9K followers) demonstrated running a home lab with no port forwarding at all: a Proxmox server as a Tailscale exit node so all traffic routes through home, RustDesk for remote desktop, and Tailscale SSH for terminal access. On Sept 11, @shotbycande (1.9K followers) named port forwarding as the number-one homelab mistake, saying it invites attackers, and recommended Tailscale or Twingate instead. Nothing here is a new product; it is the current best-practice stack being reaffirmed by three independent creators in the same week.

## Finding 3
Interest continues in Headscale, the open-source self-hosted control server that lets official Tailscale clients point at infrastructure the user owns instead of Tailscale Inc.'s coordination server. A Sept 13 explainer reel (@powerful.repos, small account) pitches it as "Tailscale clients, your control," with unlimited users and devices, Nix-ready builds, containers, and your own keys. A Sept 6 tutorial (@valebyte_servers, small account) showed a working setup: docker-compose running headscale 0.29.3 with Caddy for HTTPS, creating a user, generating a 24-hour preauth key, then joining a node with --login-server and confirming a 100.64.0.1 address and ~32ms ping between devices. Both accounts are small and promotional, so this is community texture rather than news, but it is the live path for anyone who wants the tailnet without the hosted control plane.
